# Data

Inputs the simulation reads, and outputs it writes. They were one flat folder,
which meant a generated result sat beside a hand-maintained map with nothing to
say which was which — and it would only have got worse once traces started being
exported here.

```text
data/
├── maps/        road networks           input,  committed
├── scenarios/   vehicle and event runs  input,  committed
└── results/     generated output        output, mostly ignored
```

The rule: **anything under `results/` can be deleted and regenerated.** Nothing
else can.

## maps/

A road network: `intersections`, `roads`, and optionally `buildings`. Loaded by
`JsonMapLoader`, or `CsvMapLoader` for the one CSV.

| File | What it is |
|---|---|
| `district1_network.json` | The only map. 389 junctions, 730 directed roads, 1162 buildings, 243 land-cover polygons, generated by `tools/generate_osm_map.py` from OpenStreetMap. |

The hand-made toy maps that used to sit here — `small_city`, `congestion_demo`,
`accident_demo`, `density_demo` — are gone. None had buildings or land cover, so
none could carry a demand-driven scenario, and keeping them as "scenarios" in
the picker suggested otherwise. The routing benchmark now measures District 1
instead of a six-junction sketch.

`sample_map.json` and `sample_map.csv` moved to `src/test/resources/maps/`. They
are three-junction fixtures proving the JSON and CSV loaders agree, which is a
test concern, not project data.

## scenarios/

A run script: `vehicles` and `events` to seed a simulation with, matching the
body of `POST /api/simulation/initialize`.

Empty. `demo_simulation.json` was deleted: nothing read it, and its intersection
ids belonged to the old `small_city` map. The scenario format is being designed
— see `VEHICLE_FLOW.md` — and this is where it will live.

## results/

Generated. `experiment_results.json` is the one committed file here, because it
is the published routing baseline that `EXPERIMENT_RESULTS.md` quotes and
`ExperimentService` compares against; regenerate it with:

```bash
mvn -q exec:java -Dexec.mainClass=team.traffic.experiment.ExperimentRunner -Dexec.args=--write
```

Everything else written here is ignored by git — see `.gitignore`. That is where
exported traces belong: a trace is a recording of one run, it is large, and it
is reproducible from the map, the scenario and the seed, so committing it would
add weight without adding information.

Suggested naming when trace export lands, so runs stay sortable and
self-describing:

```text
results/traces/<map>-<scenario>-<yyyymmdd-hhmm>.json
```
